# 请求限流

适用版本：0.1.0-alpha.24；`requestBudgetVersion=2`。

## 1. 修复范围

公开 alpha.23 将全部 `/instance/*` 请求归入全局 `setup` 桶，每小时 200 次。本机管理页每 5 秒分别读取共享与终端状态，两条路径均请求管理连接；一个持续可见的页面约 8 分 20 秒即可耗尽旧额度，并影响安装和授权流程。

alpha.24 将已经认证的设备管理请求与匿名安装请求分离。此前按相同版本号单独部署的云端修复，也可通过 `requestBudgetVersion=2` 识别。客户端更新不等于云端已应用修复。

## 2. 当前额度

| 分类 | 每小时额度 | 范围 |
| --- | --- | --- |
| OAuth 注册 | 100 | 实例 |
| OAuth 授权 | 1000 | 实例；含 GET `/instance/finish` |
| OAuth token | 6000 | 实例 |
| 管理员登记 | 200 | 实例 |
| 匿名安装/setup | 200 | 实例 |
| 已登记设备管理传输 | 24000 | 实例级预认证防滥用上限 |
| 设备只读管理 | 3600 | 验证设备密钥和 epoch 后，按设备隔离 |
| 设备管理变更 | 200 | 验证设备密钥和 epoch 后，按设备隔离 |

只对精确的 POST 管理路由及已登记 native 路由采用设备桶。未知路径、native enroll 和伪造设备 ID 不获得该待遇。设备读取不会消耗该设备的变更额度或其他设备的读取额度；全局传输上限仍共享。

## 3. HTTP 429

超额返回 HTTP 429、`Retry-After` 和 `retryAfterSeconds`。拒绝请求不延长窗口，不清空计数器，不扩大授权。客户端应按返回时间恢复；当前旧客户端界面不保证自动退避，不能以持续刷新作为修复。

普通使用的限流错误不等于 Cloudflare 套餐用尽。先核对接口和云端实现版本，再检查账户用量。

## 4. 验证

`tests/request-budget.test.mjs` 覆盖路由分类、旧 setup 桶耗尽后的正常轮询、设备隔离、并发额度、窗口到期、重试信息和认证顺序。

`tests/private-instance-http.test.mjs` 在隔离 Worker 中完成超过旧 200 次上限的认证管理请求，再验证原连接的显式目录授权、文件读写及撤销。模拟结果不是对用户线上权限的修改。

此修复不增加终端 scope，不重置身份，不改变目录授权，也不证明中断的命令已经运行。部署后以 `/healthz` 和实际调用共同验收。
