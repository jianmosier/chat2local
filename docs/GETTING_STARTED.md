# 使用与部署

## 项目边界

每个使用者维护自己的私人网关和实例安装密码。网关验证 ChatGPT OAuth 客户端、按设备路由文件操作；每台电脑独立保存设备身份和共享目录。新设备接入不依赖已连接的旧电脑在线。当前自托管适配器为 Cloudflare Workers / Durable Objects / KV。

源码与安装包不包含任何维护者的实际实例域名、云账号、KV 标识、设备密钥、私人路径、操作日志或内部交接记录。GitHub 仓库地址是公开源码来源，不是文件中继。

## 首次部署自己的网关

从 README 的公开 bootstrap 命令开始。脚本下载固定版本源码、官方 Node 压缩包和校验信息；新电脑不需要预装开发环境。首次执行会：

1. 让你通过官方网页登录自己的 Cloudflare 账号；多个账号时由你选择。没有账号时先完成云厂商的正常注册。
2. 经明确确认后，在你的账号创建专属 Worker 和 OAuth KV，持久化配置步骤；必要时选定自己账号的 workers.dev 子域名。
3. 配置原生客户端与首台设备接入，输出你自己的 `/mcp` 地址。
4. 你在 ChatGPT 正常添加这个 MCP 地址、选择共享目录并确认权限。平台不提供的静默安装不会被虚构。
5. 设置一次实例安装密码，后续新电脑使用这个密码加入原连接，不需要传邀请文件。

云资源、登录及安装密码都由你所有；源代码从不自动升级套餐、不接受服务条款、不读取其他应用的凭据。服务商用量及收费以你的账号为准。

全新第三方云账号的自动配置仍处于 Alpha 验收阶段。失败时不要删除配置重来；保存的 `.artifacts/selfhost-setup.json` 用于核对已创建的资源，防止不确定结果被当成未创建。

## 新增电脑

在目标电脑运行 README 中带 `--instance` / `-Instance` 的命令，实例地址使用你自己的 HTTPS 域名。程序生成该电脑自己的凭据；云端安装密码只用于首次接入新的设备，不提供读取其他电脑文件的权利。选择本机目录并确认后，原插件自动出现该设备。

## 管理现有目录

打开已安装的 Chat2Local 启动入口，进入“管理共享文件夹”。它通过本机控制会话与已经登记的设备身份核对原连接，不需要实例安装密码。勾选多个目录，查看各自的只读或读写模式，然后统一确认一次。

准备变更只读取目录元数据，不共享目录。实际确认持久化后，先保存本机权限，再激活对应云端范围；断线恢复核对同一个请求，不自动重放文件修改。正在进行的其他设备工作不受影响。新页面当前以批量新增为主；完整权限编辑和 ChatGPT 内嵌授权卡片仍在后续范围内。

## 升级与恢复

版本安装目录互不覆盖。升级已运行版本时只请求经过认证的空闲本机进程正常退出，拒绝关闭未知、暂停或繁忙进程；不会批量杀 Node、重置目录或复制设备密钥。升级会核对原配置保留。新版本启动失败不伪称成功，旧程序文件和用户配置继续保留。

这是用户级程序，不依赖浏览器页面常开。登录后自启是独立设置，不能把网络重连测试当作整机重启验收。

## 安全与开发

文件工具包括设备发现、授权目录列表、目录枚举、文本读写、建议写入和操作状态。另有独立授权的异步终端执行/查询/取消工具；其权限与风险见 TERMINAL.md，不沿用文件写权限。文件 `files:write` 并不允许远程模型自行扩展目录。日常管理 API 仅对本机经过认证且来源正确的浏览器开放；路径和权限仍在客户端落盘前再次校验。

完整套件使用 Windows/Edge + Miniflare；跨平台模拟不是物理 Mac/Linux 全系统验证。Windows 和 Apple Silicon Mac 的真实文件访问已验证过先前版本；新功能以其对应测试和实际运行结果为准。
