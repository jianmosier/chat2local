# 安装与配对

适用版本：0.1.0-alpha.24。日常回连和更新见 [OPERATIONS.md](OPERATIONS.md)。

## 1. 术语

| 名称 | 含义 | 保存位置 |
| --- | --- | --- |
| 实例 | 自己的云端网关，一套实例服务自己的多台电脑 | Cloudflare |
| 设备身份 | 每台电脑独立的设备 ID 与凭据 | 该电脑的私有状态目录 |
| ChatGPT 连接 | ChatGPT 对本实例的 MCP/OAuth 连接 | ChatGPT 与网关 |
| 实例安装密码 | 允许新设备申请加入实例的密码，不是文件访问令牌 | 实例配置；由所有者保管 |
| 本机管理会话 | 本机浏览器管理共享范围的会话 | 本机；不等于 ChatGPT OAuth |
| 共享目录 | 本机明确授权，并激活到指定连接的目录记录 | 本机与网关 |

## 2. 首次创建实例

### 2.1 前提

- 使用自己的普通桌面用户，不使用管理员终端或 sudo。
- 具备 Cloudflare 账号及资源创建权限；账号条款、套餐和用量由本人决定。
- ChatGPT 账号/工作区实际允许创建对应 MCP 应用。功能与界面以 [OpenAI 官方说明](https://help.openai.com/en/articles/12584461-developer-mode-and-mcp-apps-in-chatgpt) 和当前账号入口为准。

Windows 与 macOS 命令统一放在 [README](../README.md#3-首次创建实例)，避免多处版本漂移。无需预装 Node、Git、Codex 或 DevSpace。

### 2.2 配置步骤

| 步骤 | 用户操作 | 完成判据 |
| --- | --- | --- |
| 1. 启动安装 | 在目标电脑执行公开安装命令 | 下载及 SHA-256 校验通过 |
| 2. 云账号登录 | 在官方网页登录自己的 Cloudflare；多账号时明确选择 | 脚本识别已授权账号 |
| 3. 创建实例 | 确认创建私人 Worker、OAuth KV 与设备状态资源 | 获得自己的 HTTPS 实例地址 |
| 4. 安装本机客户端 | 由安装流程登记首台电脑，保留稳定启动入口 | 设备身份保存在本机，客户端可以连接网关 |
| 5. 添加 ChatGPT 应用 | 使用脚本输出的完整 `/mcp` 地址，按平台流程选择 OAuth、扫描工具并确认 | ChatGPT 保存该应用；授权流程完成 |
| 6. 本机目录授权 | 在该电脑的授权页核对目录、文件模式和命令风险，明确确认 | 目录在本机保存并激活到原连接 |
| 7. 设置安装密码 | 按安装流程在自己的浏览器设置实例安装密码 | 以后可用它加入新设备 |

首次向导兼容文件授权模式；它不保证自动获得全部终端能力。需要终端时，按 [PERMISSIONS.md](PERMISSIONS.md) 检查独立 scope 与本机许可，不重复选择已有目录。

安装流程中的浏览器跳转、目录选择和平台确认不能由脚本静默代办。不要把密码、OAuth 令牌、设备凭据或云端密钥粘贴到聊天中。

### 2.3 首装失败

先保留原配置与错误信息。自托管配置过程会记录已创建资源；不要删除 `.artifacts/selfhost-setup.json`、`wrangler.local.jsonc` 或本机身份后重复创建。检查失败阶段，再继续同一实例。

全新第三方 Cloudflare 账号的完整首装仍未完成端到端验收，不能将本地模拟通过写成所有新账号可用。

## 3. 新增第二台或后续电脑

1. 在新电脑执行 [README 的新增电脑命令](../README.md#4-新增电脑)，指定原实例 HTTPS 根地址，参数中不加 `/mcp`。
2. 安装器在这台新电脑打开实例安装页。输入实例安装密码。
3. 程序生成这台电脑自己的身份；随后进入本机目录授权。
4. 核对目录和权限后确认。回到原 ChatGPT 应用，重新读取设备列表。

旧电脑不必在线。不复制旧设备凭据，不需要邀请 JSON，不因新增电脑创建第二个 ChatGPT 插件。实例安装密码只允许申请设备接入，不直接提供旧电脑文件访问权。

新设备目录与命令许可仍须单独确认；原 ChatGPT 令牌未包含新能力时，也不能自动扩大 scope。

## 4. 已经配对过的电脑

| 本机状态 | 处理 |
| --- | --- |
| 身份和原连接记录仍在 | 打开已安装启动入口，复用身份进入管理页 |
| 只是暂时断网、休眠或退出程序 | 按运维指南恢复客户端，不重新配对 |
| 所有共享目录已经移除，但管理连接仍在 | 从管理页重新添加目录，不必重新安装 |
| 更换系统用户、重装系统或身份数据丢失 | 不能按旧身份回连；按新设备接入并核对旧设备记录 |
| 本机暂停或属于另一实例 | 安装器拒绝替换身份；先核对现状，不覆盖原配置 |
| 设备凭据或原连接已撤销 | 查明撤销层次，按明确的新授权处理；不能用重试恢复已撤销权限 |

普通回连不输入安装密码，不手抄配对码，不删除 ChatGPT 应用。

## 5. 日常新增目录

从稳定启动入口打开“管理共享文件夹”，选择目录、核对最终确认内容后提交。新增默认“完整共享”包含文件读写及本机命令许可；终端实际能否使用仍受 OAuth scope 限制。

旧只读、逐次审批及文件-only 授权不会自动升级。“准备”步骤只检查目录元数据；必须明确确认才能激活共享。断线后核对同一次变更的状态，不重复新建确认请求。

父子目录显示与撤销规则见 [PERMISSIONS.md](PERMISSIONS.md#3-父子目录与撤销)。

## 6. 验收

| 检查 | 合格结果 |
| --- | --- |
| 设备 | `list_devices` 返回预期设备，目标在线 |
| 目录 | 指定 `deviceId` 的 `list_roots` 返回预期目录 |
| 文件读取 | 实际 `read_file` 返回内容和哈希 |
| 直接写入 | 仅用专用测试文件，`write_file` 返回 committed/written 结果并读回一致；以实际返回状态为准 |
| 终端 | 三个终端工具存在，本机许可与 scope 同时生效；无副作用命令经状态查询得到退出码 0 |

不能用 DevSpace、另一个终端插件、本机演示按钮或服务器工具声明，代替 Chat2Local 的真实调用结果。结果未知时先查状态，不盲目重放写入或命令。
