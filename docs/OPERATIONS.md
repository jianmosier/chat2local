# 运维、回连与升级

适用版本：0.1.0-alpha.24。

## 1. 启动入口

| 平台 | 入口 |
| --- | --- |
| Windows | Win+R：`%LOCALAPPDATA%\Chat2Local\Chat2Local.cmd` |
| macOS | 终端：`open "$HOME/Applications/Chat2Local.command"` |
| 源码开发环境 | 项目目录执行 `npm run manage` |

启动器核对现有本机进程与身份，已有实例时复用；不要直接收藏带临时令牌的 localhost URL。已经验证过的同一浏览器可以恢复管理会话，新浏览器仍需由本机启动入口验证。

关闭网页不退出客户端。暂停访问、退出程序、删除共享、撤销设备和删除磁盘文件是不同操作。

## 2. 断连与恢复

| 现象 | 先检查 | 处理 | 重新配对 |
| --- | --- | --- | --- |
| 只关闭了管理网页 | 客户端是否仍在线 | 需要管理时重新打开启动入口 | 不需要 |
| 网络中断后恢复 | 本机联网与代理可用性 | Agent 用原身份自动重连 | 不需要 |
| 休眠后唤醒 | 系统已唤醒、网络已恢复 | 观察在线状态；必要时打开管理入口 | 身份有效时不需要 |
| 主动退出程序 | 本机进程是否已结束 | 打开稳定启动入口 | 不需要 |
| 重启后离线 | 是否已登录系统、是否开启自启 | 已开启则登录后启动；否则手动打开 | 不需要 |
| 本机在线，ChatGPT 认证失效 | 原应用的 OAuth 状态 | 按平台的原连接流程重新授权 | 不重建本机身份 |
| 文件可用，命令待授权 | 本机许可、scope、实际会话工具 | 按权限指南分别补齐 | 不重选已有目录 |
| 出现 HTTP 429 | 哪条接口、`Retry-After`、云端版本 | 按返回时间恢复；检查是否仍为旧云端 | 不需要 |
| 设备身份丢失或已撤销 | 系统用户、状态目录、撤销记录 | 明确核对后按新设备接入 | 可能需要 |
| 某台设备离线，另一台在线 | 调用指定的 `deviceId` | 只处理目标设备；不自动切换目标 | 不需要 |

网络机制：连接尝试超时 15 秒；断开后退避约 1、2、4、8、16、30 秒，附加小幅随机延迟；每 25 秒心跳，超过 65 秒未收到响应时关闭并重连。这些是调度参数，不是实际恢复时限承诺。

重连只恢复通道，不自动重放文件写入或命令。命令结果未知时，使用原 `requestId` 查询；不能换 ID 盲目再执行。

### 登录后自动连接

在管理页“更新与启动”开启“登录后自动连接”。它在用户登录后启动客户端，不是登录前的系统服务，不保证关机、休眠或无网络时可访问；主动退出后不会强行拉起。升级保留原开关，不能把用户关闭的自启重新打开。

## 3. 升级

### 3.1 四个独立对象

| 对象 | 更新方式 | 不会自动完成的事项 |
| --- | --- | --- |
| 本机客户端 | 管理页生成的本机更新命令，或公开入口带原实例地址 | 不部署 Worker、不扩大 OAuth 权限 |
| 云端网关 | 实例所有者从已验证源码部署到原 Worker | 不升级离线电脑、不替用户确认权限 |
| ChatGPT 工具列表 | 按账号/工作区实际支持的刷新、审核、发布流程 | 不把服务器新工具自动启用 |
| GitHub Release | 发布脚本测试、导出、打包、下载核对后发布 | 不证明用户客户端和云端均已更新 |

比较版本时分别记录客户端 `version`、云端 `/healthz.version`、`requestBudgetVersion`、源码提交和 Release 标签。仅看到相同版本字符串，不能证明整套部署来自相同构建。

### 3.2 客户端升级

1. 打开管理页“更新与启动”，使用当前电脑生成的更新命令。
2. 确认命令指向原实例。程序以独立版本目录安装，保留设备身份与共享记录。
3. 更新只允许经过认证的空闲旧进程正常退出；遇到繁忙、暂停或未知进程停止升级，不批量杀 Node。
4. 启动后核对版本、原设备、原目录、原权限和自启状态。

离线 Mac 需要在该 Mac 上升级；Windows 更新成功不代表 Mac 已升级。旧程序和用户配置保留不等于自动回滚已完成。

### 3.3 云端升级

以下操作仅由实例所有者在维护源码目录执行。先获取新版本源码，保留原 Worker 名称、域名、账号、KV、Durable Object 绑定和密钥。不重新执行无参数“首次创建实例”来更新已有网关。

```sh
npm ci --ignore-scripts
npm run verify
node --use-env-proxy node_modules/wrangler/bin/wrangler.js deploy --config wrangler.local.jsonc --dry-run
# 确认 dry-run、原资源绑定及安装资源版本后，再部署原实例：
node --use-env-proxy node_modules/wrangler/bin/wrangler.js deploy --config wrangler.local.jsonc
```

自托管的私有部署配置不提交到 GitHub。带安装静态资源的实例，还需确认安装页、脚本和客户端包指向相同发行版；仅更新 Worker 代码不会自动更新这些资源。固定版本的 `PUBLIC_BOOTSTRAP_URL` 也必须核对，不保留旧标签而声称已更新入口。

部署后检查：`/healthz` 为预期版本且 `requestBudgetVersion` 为 2；未认证 `/mcp` 仍拒绝访问；原设备连接、原目录和实际工具调用保持正常。部署记录不代替上述验收。

### 3.4 ChatGPT 工具与 OAuth

服务器增加或调整工具后，平台可能仍保存旧工具快照。按 [OpenAI 官方流程](https://help.openai.com/en/articles/12584461-developer-mode-and-mcp-apps-in-chatgpt) 处理当前账号/工作区，不假定所有套餐都提供同一个刷新按钮。新增 scope 仍须明确授权。

不要删除本机身份或重选文件夹来处理平台工具快照问题。

## 4. 状态与隐私

客户端状态目录包含设备身份、共享目录、管理会话、日志和命令记录。Windows 敏感状态使用 CurrentUser DPAPI；非 Windows 目前依赖用户级文件权限，不等同于系统密钥链加密。

故障报告只提供必要错误码、版本和脱敏后的接口路径。不要公开上传 `vault.json`、`session.json`、私有部署配置、命令输出或完整日志。

## 5. 未完成的验收

全新第三方云账号首装、各平台真实整机重启、长时间无人值守、应用签名/公证与独立安全审计仍需单独验收。网络重连测试和模拟系统测试不能替代这些结果。
